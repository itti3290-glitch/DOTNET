# תיעוד נקודות הקצה (Endpoints) ב-Swagger: Library API

כתובת Swagger בהרצה מקומית: `http://localhost:5188/swagger`

---

## 0. מושגים כלליים

### אימות (JWT)
- כל נקודת קצה, חוץ מ-`login` ו-`register`, דורשת טוקן.
- מקבלים טוקן מ-`POST /api/auth/login`, לוחצים **Authorize** למעלה בצד ימין ומדביקים אותו **בלי** המילה `Bearer`.
- הטוקן תקף 60 דקות (`Jwt:ExpiryMinutes`).
- בתוך הטוקן נשמרים: מזהה המשתמש, המייל והתפקיד (`Admin` או `Member`).

### תפקידים
| תפקיד | מי זה |
|---|---|
| `Admin` | מנהל. מנהל ה-Seed הוא `admin@library.local`, סיסמת פיתוח `Admin123!`. |
| `Member` | חבר ספרייה. נוצר דרך `register`. |

### קודי תשובה שחוזרים בכל מקום
| קוד | משמעות | מי מחזיר |
|---|---|---|
| 401 | אין טוקן, טוקן פג או טוקן לא תקין | מנגנון ה-JWT. הגוף ריק. |
| 401 | אימייל או סיסמה שגויים (רק ב-login) | ה-Middleware, עם JSON |
| 403 | יש טוקן, אבל אין הרשאה לפעולה | מנגנון ההרשאות. הגוף ריק. |
| 400 | קלט לא תקין, או הפרת כלל עסקי | ה-Middleware |
| 404 | הרשומה לא נמצאה | ה-Middleware |
| 409 | התנגשות: אין עותקים פנויים, או שמישהו אחר שינה את אותה שורה בו-זמנית | ה-Middleware |
| 500 | תקלה לא צפויה | ה-Middleware. ההודעה כללית, בלי פרטים פנימיים. |

### מבנה שגיאה אחיד (מה-Middleware)
```json
{
  "status": 409,
  "error": "Conflict",
  "message": "No copies of book 3 are currently available.",
  "correlationId": "3f9c1e5a7b2d4c68a1d0e94b5f6a7c82"
}
```
ה-`correlationId` זהה לכותרת `X-Correlation-Id` בתשובה ולמזהה בכל שורת לוג של אותה בקשה, כך שאפשר לשחזר בקשה שלמה מתוך קובץ הלוג.

### עימוד (Paging)
נקודות קצה שמחזירות רשימה מקבלות פרמטרים ב-Query:
- `page`: מספר העמוד, ברירת מחדל 1.
- `pageSize`: גודל העמוד, ברירת מחדל 20 ומקסימום 100.

התשובה:
```json
{ "items": [ ... ], "page": 1, "pageSize": 20, "totalCount": 3, "totalPages": 1 }
```
העימוד מתבצע במסד הנתונים (`Skip`/`Take`), ולא בזיכרון השרת.

## 1. Auth: `/api/auth`
פתוח לכולם, בלי טוקן.

### 1.1 `POST /api/auth/login`
**מטרה:** התחברות וקבלת טוקן.

**גוף הבקשה:**
```json
{ "email": "admin@library.local", "password": "Admin123!" }
```

**מה קורה:**
1. `AuthController` קורא ל-`AuthService.ValidateCredentialsAsync`.
2. השירות מחפש את החבר לפי מייל.
3. הוא בודק את הסיסמה מול ה-Hash השמור (PBKDF2, בהשוואה בזמן קבוע).
4. אם הכול תקין, `TokenService` יוצר JWT חתום (HS256).

**תשובות:**
- **200:** `{ "token": "...", "expiresAtUtc": "...", "member": { id, fullName, email, role } }`
- **401:** מייל לא קיים, סיסמה שגויה או מייל ריק. זו אותה הודעה בדיוק בכל המקרים, כדי שאי אפשר יהיה לגלות אילו מיילים רשומים.

### 1.2 `POST /api/auth/register`
**מטרה:** יצירת חשבון חבר חדש.

**גוף הבקשה:**
```json
{ "fullName": "Dana Cohen", "email": "dana.c@example.com", "password": "Passw0rd!" }
```

**מה קורה:**
1. `MemberService.CreateAsync` מאמת: שם לא ריק, מייל שמכיל `@`, סיסמה של 8 תווים לפחות.
2. הוא בודק שהמייל לא רשום כבר.
3. הוא מצפין את הסיסמה (`PasswordHasher.Hash`).
4. הוא קובע את התפקיד `Member`. אי אפשר ליצור Admin דרך נקודה זו.
5. הוא שומר במסד הנתונים.

**תשובות:**
- **201:** פרטי החבר, ובכותרת `Location` הכתובת `/api/members/{id}`.
- **400:** שדה חסר, מייל לא תקין, סיסמה קצרה או מייל שכבר קיים.

## 2. Books: `/api/books`
כל הבקר דורש התחברות. פעולות כתיבה דורשות `Admin`.

### 2.1 `GET /api/books`
**מטרה:** רשימת ספרים עם חיפוש, סינון, מיון ועימוד.
**גישה:** כל משתמש מחובר.

**פרמטרים ב-Query (כולם אופציונליים):**
| פרמטר | משמעות | דוגמה |
|---|---|---|
| `search` | חיפוש חלקי בכותרת, במחבר או ב-ISBN | `search=clean` |
| `author` | סינון לפי מחבר (התאמה חלקית) | `author=herbert` |
| `categoryId` | רק ספרים בקטגוריה מסוימת | `categoryId=1` |
| `availableOnly` | `true` מציג רק ספרים עם עותק פנוי | `availableOnly=true` |
| `sortBy` | `Title` (ברירת מחדל), `Author` או `Availability` | `sortBy=Author` |
| `desc` | `true` למיון יורד | `desc=true` |
| `page`, `pageSize` | עימוד | `page=2&pageSize=10` |

ערך לא חוקי ב-`sortBy` מחזיר 400. אפשר לשלב כמה פרמטרים יחד.

**מה קורה:** `BookRepository.GetPagedAsync` בונה שאילתה אחת ב-SQL. הסינון (`WHERE`), הספירה, המיון והעימוד (`Skip`/`Take`) כולם מתבצעים במסד הנתונים ולא בזיכרון, בלי מעקב (`AsNoTracking`). המיון מוגבל לרשימה קבועה של עמודות, ותמיד יש מיון משני לפי `Id` כדי שהעימוד יהיה יציב. תווים כמו `%` בחיפוש מטופלים כטקסט רגיל.
**תשובות:** 200 עם `PagedResult<BookResponse>`. כל ספר מכיל `id`, `title`, `author`, `isbn`, `totalCopies`, `availableCopies` ו-`categories`.

### 2.2 `GET /api/books/{id}`
**מטרה:** ספר בודד.
**גישה:** כל משתמש מחובר.
**תשובות:** 200 עם הספר, או 404 אם אינו קיים.

### 2.3 `POST /api/books`
**מטרה:** הוספת ספר חדש.
**גישה:** `Admin` בלבד.

**גוף הבקשה:**
```json
{
  "title": "Clean Architecture",
  "author": "Robert C. Martin",
  "isbn": "9780134494166",
  "totalCopies": 4,
  "categoryIds": [1]
}
```

**מה קורה:**
1. אימות: כותרת, מחבר ו-ISBN לא ריקים, ו-`totalCopies` אינו שלילי.
2. בדיקה שה-ISBN לא קיים כבר.
3. `availableCopies` מוגדר אוטומטית להיות שווה ל-`totalCopies`.
4. הקטגוריות נטענות לפי המזהים. מזהה שלא קיים גורם לשגיאה.
5. שמירה.

**תשובות:**
- **201:** הספר החדש, ובכותרת `Location` הכתובת `/api/books/{id}`.
- **400:** שדה חסר, מספר עותקים שלילי, ISBN כפול או קטגוריה לא קיימת.
- **401/403:** אין טוקן, או שהמשתמש אינו Admin.

### 2.4 `PUT /api/books/{id}`
**מטרה:** עדכון פרטי ספר.
**גישה:** `Admin` בלבד.

**גוף הבקשה:** כמו ביצירה (`title`, `author`, `isbn`, `totalCopies`, `categoryIds`).

**מה קורה:**
1. הספר נטען עם מעקב.
2. בדיקה שה-ISBN החדש לא שייך לספר אחר.
3. חישוב כמה עותקים מושאלים כרגע: `totalCopies − availableCopies`.
4. אם `totalCopies` החדש קטן ממספר המושאלים, הבקשה נדחית.
5. `availableCopies` מחושב מחדש כ-`totalCopies החדש − מושאלים`, כך שהעותקים המושאלים לא נעלמים.
6. הקטגוריות מוחלפות ואז נשמר.

**תשובות:**
- **204:** הצלחה, בלי גוף.
- **400:** נתון לא תקין, ISBN כפול, או ירידה מתחת למספר העותקים המושאלים.
- **404:** הספר לא נמצא.
- **409:** מישהו אחר שינה את הספר בו-זמנית (`RowVersion` השתנה).

### 2.5 `DELETE /api/books/{id}`
**מטרה:** מחיקת ספר.
**גישה:** `Admin` בלבד.
**מה קורה:** אם קיימת היסטוריית השאלות של הספר (גם השאלות שהוחזרו), המחיקה נחסמת כדי לא לאבד היסטוריה.
**תשובות:** 204 בהצלחה, 404 אם הספר לא נמצא, 400 אם יש היסטוריית השאלות.

## 3. Members: `/api/members`
כל הבקר דורש התחברות.

### 3.1 `GET /api/members`
**מטרה:** רשימת כל החברים עם עימוד, ממוינת לפי שם.
**גישה:** `Admin` בלבד.
**תשובות:** 200 עם `PagedResult<MemberResponse>`. אין שם שדה סיסמה. חבר רגיל מקבל 403.

### 3.2 `GET /api/members/{id}`
**מטרה:** פרטי חבר.
**גישה:** `Admin`, או החבר עצמו.
**מה קורה:** אם המשתמש אינו Admin ומזהה הטוקן שלו שונה מ-`id`, מוחזר 403.
**תשובות:** 200, 403 או 404.

### 3.3 `PUT /api/members/{id}`
**מטרה:** עדכון שם ומייל.
**גישה:** `Admin` בלבד.

**גוף הבקשה:**
```json
{ "fullName": "Dana Levi", "email": "dana@library.local" }
```

**מה קורה:** אימות שם ומייל, בדיקה שהמייל לא שייך לחבר אחר, ושמירה. לא ניתן לשנות סיסמה או תפקיד בנקודה זו.
**תשובות:** 204, 400 (נתון לא תקין או מייל תפוס) או 404.

### 3.4 `DELETE /api/members/{id}`
**מטרה:** מחיקת חבר.
**גישה:** `Admin` בלבד.
**מה קורה:** חבר עם היסטוריית השאלות לא ניתן למחיקה.
**תשובות:** 204, 400 או 404.

## 4. Loans: `/api/loans`
כל הבקר דורש התחברות.

### 4.1 `POST /api/loans/borrow`: השאלת ספר
**מטרה:** השאלת עותק אחד של ספר.
**גישה:** `Admin` מכל חבר. חבר רגיל רק על עצמו.

**גוף הבקשה:**
```json
{ "bookId": 3, "memberId": 1 }
```

**מה קורה, לפי הסדר:**
1. **בקר:** אם המשתמש אינו Admin ו-`memberId` אינו המזהה שלו, מוחזר 403.
2. **שירות:** טוען את הספר עם מעקב ושומר את ה-`RowVersion` שלו.
3. בודק שהחבר קיים.
4. בודק שלחבר אין כבר השאלה פתוחה של אותו ספר.
5. קורא ל-`Book.TakeCopy()`, שזורקת שגיאה אם אין עותקים זמינים, ואחרת מפחיתה `availableCopies`.
6. יוצר רשומת `Loan` עם `LoanedAt` בזמן UTC.
7. `UnitOfWork.SaveChangesAsync` שומר את ההפחתה ואת ההשאלה בטרנזקציה אחת.
8. אם מישהו אחר שינה את הספר בין הטעינה לשמירה, נזרקת `ConcurrencyConflictException` ושום דבר לא נשמר.

**תרחיש תחרות:** ספר אחרון, שני חברים לוחצים בו-זמנית. אחד מקבל 201 והשני מקבל 409, ואין מצב של `availableCopies` שלילי. גם אילוצי CHECK במסד הנתונים מגנים על זה.

**תשובות:**
- **201:** ההשאלה (`id`, `bookId`, `bookTitle`, `memberId`, `memberName`, `loanedAt`, `returnedAt`, `status`), ובכותרת `Location` הכתובת `/api/loans/{id}`.
- **403:** חבר רגיל מנסה להשאיל על שם מישהו אחר.
- **404:** ספר או חבר לא קיימים.
- **400:** לחבר כבר יש השאלה פעילה של הספר.
- **409:** אין עותקים פנויים, או התנגשות בו-זמנית.

### 4.2 `POST /api/loans/return`: החזרת ספר
**מטרה:** החזרת עותק שהושאל.
**גישה:** `Admin` על כל השאלה. חבר רגיל רק על ההשאלות שלו.

**גוף הבקשה:**
```json
{ "loanId": 1 }
```

**מה קורה:**
1. אם המשתמש אינו Admin, נטענת ההשאלה ונבדק שהיא שלו. אם לא, מוחזר 403.
2. השירות טוען את ההשאלה יחד עם הספר.
3. אם היא כבר הוחזרה, הבקשה נדחית.
4. קורא ל-`Book.ReturnCopy()`, שמגדילה את `availableCopies` ולא נותנת לעבור את `totalCopies`.
5. מציב `ReturnedAt` בזמן UTC ושומר בבדיקת התנגשות.

**תשובות:**
- **200:** ההשאלה המעודכנת עם `status: "Returned"`.
- **403:** ההשאלה שייכת לחבר אחר.
- **404:** ההשאלה לא נמצאה.
- **400:** ההשאלה כבר הוחזרה.
- **409:** התנגשות בו-זמנית על הספר.

### 4.3 `GET /api/loans/active`
**מטרה:** רשימת השאלות פעילות (שעדיין לא הוחזרו) עם עימוד.
**גישה:** כל משתמש מחובר.
**מה קורה:** `Admin` רואה את כל ההשאלות הפעילות. חבר רגיל רואה רק את שלו. הרשימה ממוינת מהחדש לישן.
**תשובות:** 200 עם `PagedResult<LoanResponse>`.

### 4.4 `GET /api/loans/{id}`
**מטרה:** השאלה בודדת. זו גם הכתובת שמופיעה ב-`Location` אחרי `borrow`.
**גישה:** `Admin`, או החבר שבשמו ההשאלה.
**תשובות:** 200, 403 או 404.

## 5. תרחיש בדיקה מומלץ ב-Swagger

1. `POST /api/auth/login` עם ה-Admin, מעתיקים את הטוקן ולוחצים **Authorize**.
2. `GET /api/books`: רואים 3 ספרים. *Dune* (מזהה 3) הוא בעל עותק אחד.
3. `POST /api/loans/borrow` עם `{ "bookId": 3, "memberId": 1 }`: מתקבל 201.
4. אותה בקשה שוב: מתקבל 400, כי לחבר כבר יש השאלה פעילה.
5. `POST /api/auth/register` ליצירת חבר חדש, ואז `borrow` על *Dune* עבורו: מתקבל 409, כי אין עותקים פנויים.
6. `GET /api/loans/active`: רואים את ההשאלה הפתוחה.
7. `POST /api/loans/return` עם `{ "loanId": 1 }`: מתקבל 200. ה-`availableCopies` של *Dune* חוזר ל-1.
8. מתחברים כחבר החדש: `GET /api/members` מחזיר 403, ו-`POST /api/books` מחזיר 403.
9. `POST /api/books` בלי טוקן: מתקבל 401.

## 6. הערות
- מי שלא מחובר מקבל 401 או 403 עם גוף ריק, כי אלה מנגנוני ה-JWT של ASP.NET ולא ה-Middleware של הפרויקט.
- מפתח ה-JWT ב-`appsettings.json` הוא מפתח פיתוח בלבד, ויש להעביר אותו ל-User Secrets לפני שימוש אמיתי.
- סיסמת ה-Admin `Admin123!` היא לפיתוח בלבד.
- מסד הנתונים של הפרויקט הוא `LibraryApiDb` ב-LocalDB.
